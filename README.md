# DreamCraft

## Download

Get the latest release, including the prebuilt Windows executable and SHA-256 checksum, from the [DreamCraft releases page](https://github.com/deadcodeXO/DreamCraft/releases/latest).

DreamCraft is a Rust-powered local website design studio. It serves the editor on 127.0.0.1:4387 and starts with the editable website in site/.

## Run it

    cargo run

On Windows this opens DreamCraft in its own native WebView2 window. On other operating systems it opens the local editor in the default browser. Set `DREAMCRAFT_NO_BROWSER=1` to run only the local server, then open its printed loopback URL yourself.

## Production executable

On Windows, run `cargo build --release` and launch `target/release/dreamcraft.exe`. The executable embeds the editor UI and starter website, so it can run from any working directory without a separate `assets` folder or source checkout. DreamCraft opens in its own native WebView2 desktop window, preceded by a compact themed startup window whose progress follows server startup, editor page load, and workspace initialization. It uses port 4387 when available and selects a free local port if 4387 is occupied. Microsoft Edge WebView2 Runtime is required. The app stores workspace history, snippets, its WebView profile, and its starter project under the current user's application-data folder; projects you open continue to live at their selected paths. Set `DREAMCRAFT_NO_BROWSER=1` to start only the local server without opening a desktop window (useful for service and HTTP smoke-check workflows). Other operating systems currently open the local editor in the default browser.

## Editor features

- Persistent dark and light editor themes with coordinated colors for the workbench, code editor and syntax tokens, controls, dialogs, code hints, reports, database panels, and scrollbars; the website preview retains the site’s own colors
- Live HTML preview with desktop, tablet, and mobile canvas widths; the last selected device preview is saved on this computer
- Configurable external-browser preview for detected Edge, Chrome, Firefox, and Brave installations; DreamCraft publishes a local snapshot and opens only same-origin published preview URLs
- Configurable dynamic testing-server process: PHP, Node, Python, or another installed executable can serve the active project; per-argument `{port}` and `{project}` substitution, loopback-only readiness checks, browser preview, and process cleanup on project switch or app shutdown
- Design, split, and syntax-highlighted CodeMirror source views with automatic and on-demand project-aware completion for HTML tags, attributes, local paths, IDs, classes, CSS selectors, declarations, values, JavaScript identifiers, PHP built-ins/superglobals, and project-defined PHP symbols
- A Code / Code split view with two synchronized source panes, independent cursors and scrolling, plus related local CSS and JavaScript file links on HTML documents
- Persistent, keyboard-accessible explorer and inspector resizing and visibility controls; drag panel edges, use arrow keys, double-click to restore a width, or use the command palette to toggle and reset panels
- Dock the Files and Inspector panels in alternate positions and save named workspace layouts with their widths and visibility settings
- Live external-browser preview served from the active site, with automatic reloads after saved changes; optionally start a token-protected, read-only Wi-Fi preview for a phone or tablet, copy its device URL, and stop sharing from DreamCraft
- Emmet-style Tab expansion for HTML tree abbreviations, groups, classes, IDs, attributes, text, and repeat counts, plus common CSS property/value shorthands; Ctrl/Cmd+E expands explicitly
- Fold and unfold nested HTML/XML elements and brace-delimited CSS/JavaScript blocks from the gutter, cursor, command palette, or document-wide fold commands
- Ctrl/Cmd+K quick open for project files and searchable editor commands, including view modes, validation, formatting, Git, Dream AI, publishing, snapshots, assets, and visual insert tools
- Local Prettier formatting for HTML, Vue, CSS, SCSS, Less, JavaScript, TypeScript, JSON, and Markdown
- Sass, SCSS, indented Sass, and Less compilation into project CSS, with import resolution, expanded/compressed output, configurable per-file destinations, automatic change watching, compiler diagnostics, and live-preview links to generated styles; Sass runs in the Rust process, and the Apache-2.0 Less.js compiler is bundled with DreamCraft
- Visual element selection, layer navigation, and live text, class, color, spacing, layout, and typography editing
- CSS Designer creates and attaches CSS files to HTML pages with relative links, matches selected page elements to linked project rules, evaluates active media/support conditions in the isolated preview, creates responsive media queries and selector rules, edits declarations in the original stylesheet, and preserves stylesheet source outside the edited declarations
- Visual Media Queries scans linked project stylesheets, draws color-coded min/max/range breakpoint bands, previews pages at exact responsive widths, updates media-query width breakpoints by dragging their visual edges, and jumps directly to the authored CSS source; the ruler has a persistent show/hide control
- Automatic local saves and a persistent multi-site manager for opening existing website folders with a themed in-app drive/folder browser and creating sites from complete responsive studio, product, and editorial starters
- Per-tab cursor and undo/redo history for source, formatting, AI, and visual-design changes
- Project file explorer, with file operations, Git, snapshots, validation, preview, and publishing scoped to the active website
- Create, rename, and delete files and folders
- New HTML files open as clean, valid documents with filename-derived titles and a project-relative link to an existing stylesheet; image insertion collects per-image alternative text, with empty text reserved for decorative images
- Project-wide Find/Replace across web source files, with case-sensitive, whole-word, and regular-expression modes, per-file replacement preview, and an automatic recovery snapshot before applying edits
- Persistent reusable code snippets with categories, searchable triggers, syntax metadata, cursor insertion, selection wrapping, and JSON import/export; snippet settings are stored in the application settings folder and follow the user across websites
- Searchable project asset library with image thumbnails and intrinsic dimensions, font and media type filters, relative-path copy, direct accessible HTML image insertion, CSS `url()` insertion, and multi-file image/font upload into the project
- Built-in HTML, local reference, accessibility, CSS structure, and JavaScript syntax checks
- Debounced live diagnostics while editing HTML, SVG, CSS preprocessors, JavaScript, TypeScript, and JSON, with a persistent enable/disable control and an Output panel whose findings jump to their source lines
- Cancellable site reports across every HTML page, authored CSS stylesheet, and authored JavaScript/TypeScript file for broken local references, missing image alternatives, duplicate IDs, document metadata, and HTML/CSS/JavaScript browser compatibility against configurable Chrome, Edge, Firefox, and Safari minimum versions using an offline MDN BCD snapshot; findings open the source at the reported line. Optional headless runs in installed Edge, Chrome, Chromium, or Brave capture uncaught exceptions, JavaScript console errors, failed requests, and HTTP error responses
- Project SQLite database browser with automatic database discovery, safe project-local database creation, table/view and column inspection, a parameterized SQL workbench, bounded result previews, and query execution for schema/data changes
- MySQL and PostgreSQL session connections with TLS options, schema/table/column inspection, and a parameterized SQL workbench; credentials are held in process memory and cleared on disconnect or app exit
- Schema-driven PHP/PDO data-bound page generation for SQLite, MySQL, and PostgreSQL with prepared create/update/delete forms, parameterized text search, 25-row pagination, CSRF tokens, escaped output, composite-primary-key support, a responsive record view, and PHP syntax highlighting; generated code opens directly in the editor and runs through the configured PHP server
- PHP login and access-control generation from a selected database table, with username/password-hash column mapping, password_verify, secure sessions, CSRF-protected login/logout, optional existing-page guards, and a recovery snapshot before writes; runtime tested with PHP 8.3 and SQLite, with generated MySQL/PostgreSQL code syntax checked
- `node tools/test-php-scaffolder-runtime.mjs` runs generated PHP 8.3 against a temporary SQLite database in Docker and verifies create, update, delete, CSRF rejection, search, pagination, and SQL injection handling. It requires Docker and downloads `php:8.3-cli-alpine` if the image is not cached.
- Dreamweaver-compatible HTML site templates: save an HTML design as a `.dwt` master, create editable, boolean optional, and repeating regions with standard Dreamweaver comment markers, generate linked HTML instances with per-page optional-region properties, add/remove/reorder repeating entries, preview the master merged with each page's editable content, protect locked page regions during source edits, and update dependent pages while preserving per-entry editable content, repeat counts, and optional-property choices with a recovery snapshot
- Additional starter page creation from complete responsive studio, product, and editorial pages
- Bootstrap 5.3.8 starter-page command with the official framework CSS, bundle, and license copied locally into each website; the themed Bootstrap component palette inserts responsive navigation, hero, card grid, accordion, dismissible alert, modal, button group, and grid markup into Bootstrap-enabled pages
- Git initialize, status, stage/unstage, diff, commit, history, origin, fetch, pull, push, local branch create/switch/merge, annotated tags and tag publishing, and confirmation-gated commit reverts
- Local immutable publish snapshots with isolated HTML preview
- Snapshot history with one-click restore that creates a recovery point before replacing the current site
- SFTP publish and synchronization through the installed OpenSSH client, SSH config, and agent; browse remote folders, compare same-size files by content when readable, selectively upload/download with a recovery snapshot, and rename or delete selected remote files
- FTP and explicit FTPS publishing and recursive site comparison, with content verification, selective two-way file transfer, remote file rename and delete; FTPS verifies TLS certificates
- WebDAV publish and recursive byte-for-byte comparison, with selective two-way file transfer, remote file rename and delete, and recovery snapshots
- Share the local project or the latest published snapshot address
- Optional Dream AI Ask and Edit modes using any OpenAI-compatible chat-completions endpoint, with selectable read-only project context, cancellable requests, complete-file review, line-change previews, safe stale-file checks, and explicit apply/save

The checker reports common authoring problems and navigates to source lines; it is not an HTML/CSS/JavaScript standards certification tool. Browser compatibility findings use the bundled MDN BCD 8.1.6 snapshot for HTML, CSS, JavaScript syntax, built-ins, and Web API support. The compatibility data is offline, licensed CC0-1.0, and can be regenerated from the upstream package using tools/build-browser-compat-index.mjs. It statically analyzes authored local JavaScript and does not execute the project in each target browser or analyze server-side language compatibility. The SQLite panel operates on project `.db`, `.sqlite`, and `.sqlite3` files. MySQL and PostgreSQL are supported for live schema inspection and SQL queries, and the PHP data-page generator supports SQLite, MySQL, and PostgreSQL. Database, SFTP, FTP/FTPS, WebDAV, and Dream AI credentials are held in memory for the current app session. External-browser preview publishes a versioned local snapshot and launches the selected installed browser. Site Reports can also run a published snapshot headlessly in installed Edge, Chrome, Chromium, or Brave and capture uncaught JavaScript exceptions, browser console errors, and failed network requests. Each report can run every selected installed Chromium-family browser; Firefox and Safari remain static compatibility targets, not runtime engines. SFTP, FTP/FTPS, and WebDAV publish upload regular site files except Git metadata and DreamCraft release snapshots. They overwrite matching remote paths and leave remote-only files intact. SFTP browsing is folder-by-folder; content verification downloads matching-size remote files when possible and marks unreadable matches as unverified. SFTP and FTP/WebDAV transfers create a versioned local recovery snapshot, stage downloads before applying them, and use a stable snapshot for uploads. FTP uses MLSD with a LIST fallback for recursive comparisons; servers that provide neither listing format cannot be synchronized. FTP supports plain FTP and explicit FTPS; the UI warns before selecting unencrypted FTP. WebDAV comparison inspects remote-only, local-only, identical, and changed files. Remote and local-only files are never automatically deleted; remote file deletion requires an explicit confirmation, is limited to regular files, and excludes `.git` and `.dreamcraft` paths. Rename operations are limited to regular files in their current remote folder. All protocol synchronization operations reject unsafe paths and symlinks.

Live external previews rewrite site-root paths into the active project's local route. Published snapshots apply the matching rewrite for root-relative HTML links and sources, CSS imports, and CSS `url()` references, preserving query strings and external protocol-relative URLs. The rewriter serves the preview snapshot without modifying the site's source files.

Formatting runs fully in the browser from the vendored Prettier standalone build, so it does not require Node.js at runtime or send source code to an external formatter. The Prettier browser build does not load project configuration files.

Sass/SCSS builds run in the Rust process and resolve files through a project-confined Sass filesystem. Less builds use the Apache-2.0 Less.js browser compiler bundled into the production executable; browser JavaScript evaluation is disabled for Less sources. Generated CSS is written into the active site and can be assigned a distinct output path per source. DreamCraft watches source and imported CSS files in the background by default; turn off **Watch source files** in **Build CSS** to keep builds on demand. When a preview page links a `.scss`, `.sass`, or `.less` source, DreamCraft serves its compiled `.css` output to the preview without rewriting the HTML source. CSS Designer treats generated CSS as read-only and directs edits to the source stylesheet.

The SQLite database workbench is embedded in DreamCraft. Generated PHP authentication requires existing account rows with password hashes produced by PHP password_hash(); DreamCraft does not provision accounts or send/reset passwords. Generated PHP pages use PDO_SQLITE for project files, PDO_MYSQL for MySQL, or PDO_PGSQL for PostgreSQL. PHP and the matching PDO driver remain external runtimes. Remote PHP pages never contain database credentials: they read `DREAMCRAFT_DB_HOST`, `DREAMCRAFT_DB_PORT`, `DREAMCRAFT_DB_DATABASE`, `DREAMCRAFT_DB_USERNAME`, `DREAMCRAFT_DB_PASSWORD`, and `DREAMCRAFT_DB_TLS`  from the server environment. DreamCraft injects the currently connected session's settings into its dynamic testing-server process; on a deployed server, define the same variables in that host's secret manager. TLS-enabled pages use certificate verification; set `DREAMCRAFT_DB_CA_FILE` (or legacy `DREAMCRAFT_DB_CA_FILE`) when the database provider requires a custom CA certificate. See the official [PDO MySQL](https://www.php.net/manual/en/ref.pdo-mysql.connection.php), [PDO PostgreSQL](https://www.php.net/pdo-pgsql.connection), and [PDO SQLite](https://www.php.net/pdo-sqlite) documentation. Dynamic application servers use a runtime executable installed on the computer; DreamCraft does not bundle PHP, Node, or another web-server runtime. Configure the executable and one argument per line in the testing-server panel. For example, PHP's built-in server can use `-S`, `127.0.0.1:{port}`, `-t`, and `{project}` as four arguments.

## Dream AI

Dream AI is disabled until configured from the sparkle icon in the left toolbar. Set the API base URL and model name for an OpenAI-compatible service. A local Ollama server commonly uses http://127.0.0.1:11434/v1; hosted services may require a bearer API key.

Dream AI has two modes. Ask sends the open file, recent Ask conversation, and up to 40 selected read-only project text files (subject to per-file and total context limits) to the configured endpoint. Edit sends only the prompt and the complete open file and asks the model for a complete replacement of that one file. Edit results are rejected when empty, oversized, explicitly unavailable, or reported as truncated. Each proposed replacement has a complete-file preview and a line-change review. Before applying, DreamCraft checks that both the editor buffer and saved project file still match the version used to generate the edit. Applying requires confirmation and a successful save; if saving fails, the editor restores the previous text. No model is bundled: configure an OpenAI-compatible service, such as a local Ollama server, to enable Dream AI. API keys and connection settings are held in memory and cleared when DreamCraft closes. A prompt and selected file contents are sent only when a request is submitted.

## Project structure

- src/main.rs: local Rust server, project/Git/SFTP APIs, local publishing, and optional AI proxy
- assets/: editor UI and locally bundled CodeMirror assets
- site/: editable website project
- .dreamcraft/workspace.json: recent website folders and the active website path; website files remain in their selected folders
